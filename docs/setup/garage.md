# Garage (S3) setup

## KEY & SECRET

These are produced by `scripts/generate-prod-env.py` and live in `.env.prod`.
The rest of the stack reads them directly; **don't change the names**.

```bash
# S3 credentials the app signs requests with (imgproxy, wersu-rest).
# `--default-bucket` in compose imports this key into garage on first
# boot and grants it owner/read/write on $GARAGE_DEFAULT_BUCKET.
GARAGE_DEFAULT_ACCESS_KEY=<64-char hex>     # 32 bytes, generated
GARAGE_DEFAULT_SECRET_KEY=<64-char hex>     # 32 bytes, generated

# Bucket name (static, do not change without touching app code,
# imgproxy config, and the --default-bucket flow).
GARAGE_DEFAULT_BUCKET=garage

# Internal endpoint the app uses to reach garage over the docker
# network. Must match S3_REGION=garage in garage.toml.
S3_ENDPOINT=http://garage:3900
S3_REGION=garage
```

To find them on the server: `grep ^GARAGE_ /path/to/WerSu/.env.prod`.

## Server-side secrets (read from env, never in `garage.toml`)

`garage` reads these directly from the env at startup:

- `GARAGE_RPC_SECRET` — authenticates cluster nodes.
- `GARAGE_ADMIN_TOKEN` — gates the `/v1/*` admin API.
- `GARAGE_METRICS_TOKEN` — gates `/metrics`.

All three are 64-char hex, auto-generated by `generate-prod-env.py`.

## Auto-created on first boot

`docker-compose.prod.yaml` passes `--single-node --default-bucket` to
`garage server`. On a fresh data dir that auto-runs the layout assign,
creates the bucket, and imports the access key — no manual
`garage key create` / `garage bucket allow` needed.

## Verify on the server

```bash
docker exec wersu-garage /garage key list
docker exec wersu-garage /garage bucket list
docker exec wersu-garage /garage status
```

## Rotate

Re-run `generate-prod-env.py`, redeploy `garage wersu-rest wersu-imgproxy`.
On an existing cluster, also run `garage key import` and
`garage bucket allow --read --write --owner` for the new key.

See the [Garage quick-start](https://garagehq.deuxfleurs.fr/documentation/quick-start/).
